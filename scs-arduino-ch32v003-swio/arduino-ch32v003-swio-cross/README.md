# CH32V003 SWIO - Arduino SDK

Адаптер UART <-> SWIO для доступа к отладочным регистрам CH32V003.
Перенос проекта `arduino-ch32v003-swio` на Arduino AVR Core по структуре
`air-valve-arduino`. Основная плата - **Arduino Uno R3 / ATmega328P, 16 МГц**;
подходит также Nano с ATmega328P на 16 МГц.

## Подключение

| Arduino | Назначение |
|---------|------------|
| D8 / PB0 | SWIO CH32V003 через последовательный резистор 1 кОм |
| D9 / PB1 | Управляемое питание цели (HIGH - включено) |
| GND | Общая земля с целью |

## Сборка и прошивка

```sh
# Если Arduino AVR Core ещё не установлен:
arduino-cli core update-index
arduino-cli core install arduino:avr

make
make flash PORT=/dev/ttyACM0
make clean
```


Для Nano:

```sh
make flash FQBN=arduino:avr:nano PORT=/dev/ttyUSB0
# Nano со старым загрузчиком:
make flash FQBN=arduino:avr:nano:cpu=atmega328old PORT=/dev/ttyUSB0
```

Можно открыть `swio_adapter/swio_adapter.ino` в Arduino IDE и выбрать Uno/Nano.
Другие архитектуры и частоты не поддерживаются: драйвер проверяет MCU и F_CPU
при компиляции. Название `cross` не означает переносимость SWIO на другие MCU.

## UART-протокол

**115200 бод, 8N1**, бинарные данные, без переводов строк.
При готовности адаптер отправляет `!`. DTR штатной платы позволяет сбросить адаптер.

| Команда | Аргументы | Ответ |
|---------|-----------|-------|
| `?` | нет | `+` |
| `p` | нет | включить питание, `+` |
| `P` | нет | выключить питание, `+` |
| `w` | адрес (1 байт), значение (4 байта, little-endian) | `+` |
| `r` | адрес (1 байт) | значение (4 байта, little-endian), без `+` |

Адрес отладочного регистра - 0x00...0x7F. Старший бит адресного байта игнорируется.
Неизвестные команды игнорируются. `+` подтверждает выполнение локальной операции,
но не проверяет успешность записи на цели.

Отправляйте одну команду с аргументами и дожидайтесь ответа перед следующей.
Поток команд без ожидания не поддерживается: во время SWIO прерывания UART
отключены, и непрерывная передача может приводить к потере байтов.

## Прошивка CH32V003 через адаптер

Адаптер реализует протокол **Ardulink**, который нативно поддерживает
**minichlink** (из [cnlohr/ch32fun](https://github.com/cnlohr/ch32fun),
`minichlink/ardulink.c`). Minichlink говорит по UART-протоколу адаптера 1:1
(DTR-сброс, синхронизация `?`/`!`/`+`, `w`/`r`, `p`/`P`) и реализует поверх
уровня отладочных регистров всю логику RISC-V debug: стирание, запись,
чтение, перезапуск, gdbserver.

### Сборка minichlink

```sh
git clone https://github.com/cnlohr/ch32fun
cd ch32fun/minichlink
make      
```

### Прошивка

```sh
# Информация о чипе
./minichlink -C ardulink -c /dev/ttyUSB0 -i

# Стирание flash
./minichlink -C ardulink -c /dev/ttyUSB0 -E

# Запись .bin (0x08000000 - база flash CH32V003)
./minichlink -C ardulink -c /dev/ttyUSB0 -w obj/firmware.bin 0x08000000

# Перезапуск цели
./minichlink -C ardulink -c /dev/ttyUSB0 -b
```

`-C ardulink` - явное указание типа адаптера (без него minichlink сначала
ищет WCH-ISP, WCH-Link и другие адаптеры). `-c` - COM-порт Arduino.
Опции можно объединять: `-3Eb` - включить питание, стереть, перезапустить.

| Опция | Действие |
|-------|----------|
| `-i` | информация о чипе |
| `-E` | стирание всего flash |
| `-w file.bin ADDR` | запись |
| `-r file.bin ADDR SIZE` | вычитка flash |
| `-b` / `-e` | перезапуск / resume |
| `-3` / `-t` | питание цели вкл/выкл (команды `p`/`P`) |
| `-G` | gdbserver (отладка через `gdb-multiarch`) |

Промежуточный файл - только **raw .bin**: elf и hex minichlink не принимает.
Прошивку CH32V003 можно собрать в WCH EVT (`ch32v003/EVT/...`, `make` ->
`obj/*.bin`) или в ch32fun.

### Питание цели

Minichlink сам управляет питанием (команды `p`/`P`), поэтому цель лучше
питать через D9 Arduino: цикл "включить питание -> инициализация -> прошивка"
проходит автоматически.

## Реализация и ограничения

- `swio_adapter.ino`: `setup()` / `loop()`, аппаратный `Serial`, управление
  питанием через `pinMode()` / `digitalWrite()`.
- `swio.c/h`: исходный низкоуровневый драйвер на регистрах AVR. `digitalWrite()`
  слишком медленный для коротких импульсов SWIO; сохранён уровень оптимизации
  драйвера `-O1` через GCC pragma.
- Исправлена маска освобождения PB0: `~_BV(SWIO_BIT)` вместо `~SWIO_BIT`.
- Чтение/запись SWIO выполняются в `ATOMIC_BLOCK(ATOMIC_RESTORESTATE)`, чтобы
  прерывания Arduino Timer0 и UART не нарушали тайминги. Инициализация с длинными
  задержками выполняется с разрешёнными прерываниями. `millis()` / `micros()`
  не используются для протокола.
- Как в оригинале, нет тайм-аутов при ожидании аргументов UART и освобождения
  SWIO. При зависшей в LOW линии адаптер может зависнуть с отключёнными
  прерываниями; потребуется сброс. Проверка ошибок и контрольная сумма отсутствуют.
- Сборка не заменяет проверку на железе: тайминги, чтение/запись регистров и
  электрическое подключение необходимо проверить на реальной цели.
