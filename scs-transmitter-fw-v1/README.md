# Передатчик телеметрии Arduino Nano + CC1101

Передатчик собирает показания трёх датчиков в аэрационной станции очистки сточных вод и передаёт их по радио в дом. Эти данные нужны для наблюдения за потоком воды в эрлифтах, которые перекачивают воду между камерами станции с помощью воздуха.

Передатчик по очереди запрашивает накопленные результаты датчиков, проверяет целостность ответов и отправляет значения вместе с номерами датчиков на приёмник. Приёмник выдаёт их компьютеру для хранения и анализа. При ошибках ответа передатчик отправляет соответствующий статус.

Прошивка для ATmega328P. Бинарные ответы трёх сенсоров собираются через аппаратный UART **9600 8N1**, проверяются и передаются по радио. Внешние Arduino-библиотеки не нужны: драйвер CC1101 использует штатный `SPI`.

Сенсоры, передатчик и приёмник должны поддерживать описанный ниже бинарный протокол. Обновлять их нужно согласованно.

## Работа

1. В `setup()` D4/D5/D6 устанавливаются в HIGH (сначала выходная защёлка, затем направление).
2. Пауза `POLL_INTERVAL_MS`, по умолчанию 10 секунд, в том числе перед первым опросом.
3. Последовательно D4 -> D5 -> D6: удаление доступных старых UART-байтов, импульс LOW длительностью 2 мс и приём ответа. Номера сенсоров соответственно **3 -> 2 -> 1**. UART принимает и во время LOW.
4. После опроса всех сенсоров передаются накопленные записи в том же порядке, затем снова пауза. Время цикла равно паузе плюс время опроса и радиопередачи; догоняющих опросов нет.

## Бинарный UART-протокол

Каждая запись сенсора содержит ровно **6 байт**:

| Смещение | Поле                                |
|---------:|-------------------------------------|
|        0 | `seq`, uint8_t                      |
|      1-4 | `value_milli`, uint32_t, big-endian |
|        5 | CRC-8 байтов 0-4                    |

CRC-8/ATM: polynomial `0x07`, init `0x00`.
Контрольные векторы: `123456789 -> F4`; запись `00 00 00 00 7D 74` означает `seq=0`, `value_milli=125`.

Весь диапазон uint32_t допустим. Передатчик не масштабирует значение, не вычисляет поток или время и не анализирует последовательность `seq`.

Для каждого сенсора есть отдельный буфер на **32 полные записи (192 байта)**. Старые записи не вытесняются. Ответ завершается паузой `FRAME_GAP_MS`; общий предел приёма составляет `TIMEOUT_MS` после окончания импульса запроса.

| Статус | Значение | Поведение |
|---:|---|---|
| 0 | измерение | При нормальной паузе передаются все записи в исходном порядке, если длина кратна 6 и все CRC корректны |
| 1 | нет ответа (`NR`) | Ни одного байта до таймаута; одна запись ошибки |
| 2 | таймаут (`TO`) | К таймауту получены только полные корректные записи, но пауза не наступила: сначала все измерения, затем одна запись TO |
| 3 | ошибка протокола/CRC (`CR`) | Ошибка CRC любой записи или неполная запись при паузе/таймауте: весь ответ отбрасывается, передаётся только CR |
| 4 | переполнение (`OF`) | Получен 193-й байт: весь ответ отбрасывается, передаётся только OF |

Пустого успешного ответа нет. Первая обнаруженная терминальная ошибка определяет статус: ошибка CRC, найденная раньше 193-го байта, остаётся CR независимо от длины очищаемого хвоста. Восстановления синхронизации внутри ответа нет. Если одновременно истекли общий таймаут и межкадровая пауза, приоритет имеет таймаут.

После CR/OF/TO хвост вычитывается до паузы либо предела `DRAIN_LIMIT_MS`; очистка не меняет статус. Перед следующим запросом доступные старые байты удаляются ограниченным снимком количества. Непрерывный поток не приводит к бесконечному ожиданию.

## Радиоканал

Профиль: 433,92 МГц, кварц CC1101 26 МГц, 2-FSK, 4,8 кбод, sync D391, переменная длина.

Инициализация выполняет ручную последовательность сброса из [документации TI CC1101, раздел 19.1.2](https://www.ti.com/lit/ds/symlink/cc1101.pdf): SPI отключается, SCLK устанавливается в HIGH, SI/MOSI в LOW, затем CSn переключается LOW/HIGH с выдержкой не менее 40 мкс перед следующим LOW. После готовности SO/MISO включается SPI, выдаётся SRES и снова проверяется готовность. Все записанные регистры конфигурации и PATABLE[0] читаются обратно; несовпадение означает ошибку инициализации и повторную попытку перед передачей следующего цикла. Последовательность одинакова при холодном старте и повторной инициализации.

Каждая радиозапись содержит ровно **6 байт**:

| Смещение | Поле                                              |
|---------:|---------------------------------------------------|
|        0 | `H = (status << 4) | sensor`, sensor = 1, 2 или 3 |
|        1 | `seq`                                             |
|      2-5 | `value_milli`, big-endian                         |

Для status 1-4 поля `seq` и `value_milli` всегда нулевые. Например:

```text
03 00 00 00 00 7D   measurement, sensor 3, seq 0, value_milli 125
13 00 00 00 00 00   NR, sensor 3
23 00 00 00 00 00   TO, sensor 3
33 00 00 00 00 00   CR, sensor 3
43 00 00 00 00 00   OF, sensor 3
```

UART CRC в радиозапись не копируется, дополнительного прикладного CRC нет. Сохраняется аппаратный CRC CC1101; совместимый приёмник должен проверять `CRC_OK`.

`Radio::PAYLOAD_SIZE` равен **32**, но полезная нагрузка содержит только целые записи: **1-5 записей**, то есть **6, 12, 18, 24 или 30 байт**. Шестая запись начинает следующий пакет. Нет заголовков, разделителей, LF, заполнения или маркеров пачки. В одном пакете могут находиться записи разных сенсоров. Порядок: все записи сенсора 3, затем 2, затем 1; TO идёт после измерений своего сенсора.

Максимальный объём за цикл составляет `3 * (32 + 1) * 6 = 594` байта (32 измерения и TO для каждого сенсора), без учёта служебных байтов физических пакетов. Ёмкость и декодирование приёмника должны соответствовать описанному бинарному протоколу.

## Настройки

`scs-transmitter/config.h`, все времена в миллисекундах:

| Макрос             | По умолчанию | Значение                                     |
|--------------------|-------------:|----------------------------------------------|
| `POLL_INTERVAL_MS` |        10000 | пауза перед каждым циклом                    |
| `TIMEOUT_MS`       |         1000 | общий приём после окончания импульса запроса |
| `FRAME_GAP_MS`     |           20 | тишина после последнего байта, конец ответа  |
| `PULSE_MS`         |            2 | длительность LOW                             |
| `RECORD_SIZE`      |            6 | фиксированный размер UART- и радиозаписи     |
| `CHANNEL_CAPACITY` |           32 | фиксированная ёмкость канала в записях       |
| `DRAIN_LIMIT_MS`   |         1000 | предел очистки ошибочного ответа             |

Полная пачка сенсора содержит 192 байта и занимает около 200 мс при 9600 8N1. Таймаут 1000 мс включает завершающую паузу 20 мс и запас на начало ответа. Для произвольной задержки начала ответа отсутствие TO не гарантируется.

Проверки при компиляции фиксируют размер записи 6 и ёмкость 32 и ограничивают значения времён. Буферы статические, без Arduino `String` и динамического выделения памяти; на стеке собирается одна шестибайтовая запись.

## Сборка и тесты

Для Ubuntu 24.04 LTS и 26.04 LTS см. [инструкцию по сборке в Ubuntu](UBUNTU.md). Для автономной установки используйте архив `arduino-avr-offline-cache.tar.gz`. 

### Хост-тесты

Хост-тесты выполняют скетч с подменой Arduino/SPI и проверяют: контрольные CRC-векторы и одиночные битовые повреждения каждого байта, длины 0/1/5/6/12/191/192/193, CRC-ошибку в начале/середине/конце ответа, приоритет первой ошибки, все статусы и номера сенсоров, нулевые поля ошибок, весь диапазон uint32_t вплоть до `0xFFFFFFFF`, полный/неполный ответ при TO, приоритет таймаута над паузой, границы радиопакетов, независимость каналов и их порядок, максимальный цикл, ограниченная очистка хвоста, порядок запросов и начальная пауза, прекращение передачи при ошибке и последующая переинициализация радио, ограниченные ожидания CC1101, последовательность GPIO при сбросе радио, повторную инициализацию, обратное чтение настроек и отказ при неверных данных SPI/игнорировании записей.
