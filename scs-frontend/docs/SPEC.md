# Анализ и визуализация телеметрии септика

Статус: **утверждено пользователем**.

## Цель

Накопить данные стендовых испытаний, подобрать пороги определения потока и затем наблюдать два режима работы септика. Исследовать связь показаний датчиков с интенсивностью потока без расчёта расхода в физических единицах.

Сейчас датчики лежат на столе, размеченных наблюдений нет. Назначения каналов и признаки режимов задаются в приложении, а не фиксируются под конкретную станцию.

## Функциональные требования

### Сбор и хранение

- **FR-1.** Бэкенд непрерывно собирает телеметрию независимо от браузера. Порт настраивается, по умолчанию `/dev/ttyACM0`, скорость 115200, 8N1.
- **FR-2.** Поддерживается протокол приёмника: `BEAT`, группы `BEGIN` / `END`, измерения с SEQ, ошибки датчиков и `ERR BO`.
- **FR-3.** Исходные измерения, их порядок, SEQ, время получения группы и диагностические события сохраняются бессрочно, кроме явного удаления пользователем (FR-15-18).
- **FR-4.** Время всей группы определяется по её получению компьютером. Длительности состояний оцениваются по поступлению групп; интерфейс явно сообщает об этой приблизительности.

### Настройка датчиков и потока

- **FR-5.** Для каждого из трёх каналов задаются название и назначение, порог `T` и ширина гистерезиса `H >= 0`.
- **FR-6.** Поток включается при значении выше `T + H/2`, выключается ниже `T - H/2`. Между границами, включая равенство им, предыдущее состояние сохраняется.
- **FR-7.** До первого выхода за границы состояние неизвестно. Отсутствие данных не считается отсутствием потока.
- **FR-8.** Тайм-аут задаётся отдельно для каждого датчика, по умолчанию 60 секунд.

### Режимы

- **FR-9.** Режимов всегда два. Для каждого режима и датчика задаётся условие: "поток", "нет потока" или "не учитывать".
- **FR-10.** Если подходит ровно один режим, определяется он. Если подходят оба, ни один или недостаточно данных для однозначного решения, режим не определён.

### Анализ

- **FR-11.** Пользователь выбирает период анализа. История пересчитывается по текущим настройкам порогов и режимов, исходные данные не изменяются.
- **FR-12.** По каждому датчику рассчитываются мин/макс/медиана значений по всем измерениям периода, отдельно при наличии потока и отдельно при отсутствии потока.
- **FR-13.** Для интервалов "поток / нет потока" рассчитываются количество, суммарная, минимальная, максимальная и медианная длительности.
- **FR-14.** Для режимов рассчитываются длительность и доля времени каждого режима, число переключений, длительности отдельных интервалов. Неопределённость и отсутствие данных показываются отдельно.

### Интерфейс

Утверждённый состав:

- Текущие показания, состояния датчиков и режим.
- Графики исходных значений с границами гистерезиса.
- Временные полосы состояний датчиков и режимов.
- Таблицы статистики.
- Настройки каналов, порогов, режимов, порта и тайм-аутов.

### Удаление истории

- **FR-15.** В приложении можно удалить всю историю или данные за отдельно выбранный период `[начало, конец)`. Группы удаляются целиком по времени получения; диагностические события удаляются по собственному времени.
- **FR-16.** Удаление затрагивает измерения и диагностические события, но сохраняет все настройки. Не затронутые периодом данные сохраняются.
- **FR-17.** Перед удалением интерфейс запрашивает подтверждение с указанием области удаления. Операция необратима, автоматическая резервная копия не создаётся. Отмена не изменяет данные; некорректный период отклоняется.
- **FR-18.** Сбор продолжает работать. После удаления текущие показания, графики, статистика и список событий обновляются по оставшимся данным; вновь поступающие данные могут появиться сразу.

## Технические ограничения

- **NFR-1.** Python + FastAPI, SQLite, простой JavaScript без фронтенд-фреймворка, готовая библиотека графиков.
- **NFR-2.** Один сервис раздаёт интерфейс и REST API.
- **NFR-3.** По умолчанию доступ локальный; доступ из домашней сети включается настройкой. Авторизация и публикация в интернете не предусмотрены.
- **NFR-4.** Перезапуск приложения не теряет сохранённые данные и настройки.

## Обработка сбоев

- При отключении serial сервис продолжает работать и автоматически пытается подключиться заново.
- Незавершённая группа не используется как полноценная телеметрия; ошибка фиксируется.
- Ошибки датчика показываются сразу, но не превращаются в нулевое измерение. Тайм-аут считается от последнего корректного показания.
- После тайм-аута состояние потока сбрасывается в неизвестное; определение начинается заново.
- Пропуски SEQ отмечаются диагностически. Пропущенные значения не восстанавливаются искусственно; перезапуск датчика и оборот счётчика учитываются как ограничения диагностики.

## Ограничения интерпретации

Показания датчиков характеризуют изменчивость сигнала, а не физический расход. Индивидуальных временных меток измерений нет. Внутри группы сохраняется порядок измерений, но точное время каждого измерения неизвестно. `BEAT` показывает работу приёмника, но не поступление корректных показаний датчиков.

## Вне области работ

Автоподбор порогов, обучение, определение физического расхода, уведомления, управление септиком и изменение прошивок.

## Критерии приёмки

Ниже перечислены требования к проверкам. Результаты выполненных проверок приведены в `VERIFICATION.md`.

- **AC-1 -> FR-1-4, NFR-4:** при закрытом браузере данные продолжают сохраняться; после перезапуска история доступна.
- **AC-2 -> FR-5-8:** при `T=10`, `H=2` поток включается выше 11, выключается ниже 9; внутри петли сохраняется состояние. После тайм-аута отображается отсутствие данных.
- **AC-3 -> FR-9-10:** проверить оба режима, совпадение их условий, отсутствие совпадений и неизвестные показания.
- **AC-4 -> FR-11-14:** на заранее подготовленном наборе данных статистика совпадает с ручным расчётом; изменение порогов пересчитывает выбранный период.
- **AC-5 -> FR-2, обработка сбоев:** ошибки и разрывы соединения не создают ложных нулевых показаний или состояний "нет потока".
- **AC-6 -> NFR-2-3:** интерфейс доступен локально, сетевой доступ включается отдельно.

- **AC-7 -> FR-15-16:** удаление `[a, b)` удаляет все записи групп с `a <= время < b` и события в этом периоде; данные на границе `b`, вне периода и настройки сохраняются. Полное удаление очищает историю, но не настройки.
- **AC-8 -> FR-17:** отмена подтверждения не отправляет запрос удаления; неполный, неконечный или обратный период отклоняется без изменений. Ошибка операции не отображается как успех.
- **AC-9 -> FR-18:** после удаления интерфейс обновляет все представления истории; сбор новых групп продолжает работать. Автотесты используют отдельные БД, не реальную историю.

## Проверка

Автоматические проверки протокола, гистерезиса, определения режимов, расчёта статистики и обработки ошибок на подготовленных данных. Ручная проверка интерфейса, сбора при закрытом браузере, сохранности истории после перезапуска и работы с реальным приёмником.
