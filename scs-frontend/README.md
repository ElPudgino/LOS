# SCS: сбор и анализ телеметрии

Локальный сервис на Python/FastAPI хранит данные в SQLite и раздаёт интерфейс без фронтенд-фреймворка. Графики строит локальная копия Chart.js 4.4.8 с MIT-лицензией, интернет не требуется. UART-протокол использует `BEGIN` / `END`, HEX SEQ и `BEAT`.

## Установка и запуск в Ubuntu

См. [инструкцию для Ubuntu 24.04 и 26.04 LTS](docs/UBUNTU.md): установка зависимостей, виртуальное окружение, тесты, запуск и сборка дистрибутива.

Сервис собирает данные всё время, пока запущен, независимо от открытых браузеров.

## Правила анализа

- Время группы совпадает с Unix-временем компьютера при получении `END`. Все её записи имеют одно время, но сохраняют исходный порядок. Точное время отдельных измерений неизвестно; длительности и полосы приблизительны. Желательны стабильные часы ПК.
- Поток включается строго выше `T+H/2`, выключается строго ниже `T-H/2`. Равенство и внутренняя область сохраняют предыдущее состояние. До первого выхода за границы состояние неизвестно.
- Тайм-аут наступает при `последнее корректное измерение + timeout` (по умолчанию 60 с). Состояние сбрасывается и не восстанавливается измерением внутри петли. Ошибки не являются нулями и не продлевают тайм-аут. Последнее корректное значение остаётся видимым с его временем, но после тайм-аута состояние неизвестно.
- Период статистики: **[начало, конец)**. Состояние в начале восстанавливается по предшествующей истории с текущими настройками. Все измерения периода участвуют в статистике, даже если несколько пришли с одним временем. Значение относится к состоянию после обработки именно этого измерения. Длительность между группами задаёт последнее состояние группы; нулевые интервалы не считаются.
- Интервалы обрезаются границами периода. Число интервалов равно числу непустых непрерывных участков внутри периода. Мин/макс/медиана пустой выборки: `null`.
- Режим известен, только если один гарантированно совпал, а другой гарантированно исключён. Неизвестный учитываемый датчик не подменяется отсутствием потока. `no_data` означает, что режим не удаётся определить из-за отсутствующих/просроченных данных; `unknown` обозначает неоднозначность, несовпадение либо неизвестное состояние внутри гистерезиса при свежих данных. Неучитываемый канал не препятствует определению.
- Доли режимов считаются от всего выбранного периода, включая неопределённость и отсутствие данных. Переключениями считаются только непосредственные переходы между двумя известными режимами; переход через неизвестный участок не додумывается.
- SEQ проверяется по каналам modulo 256. Разрыв служит диагностическим событием, а не точным числом потерянных измерений: повтор, перезапуск и полные обороты счётчика неразличимы. Пропуски не заполняются искусственно.

При ошибках датчика диагностика показывается сразу. Измерения группы сохраняются атомарно только после `END`. Повреждённая/незавершённая группа не участвует в анализе; её полученные строки сохраняются в диагностике. Группа без `END` за 5 секунд отбрасывается. `ERR BO` сохраняется как переполнение приёмника, `OF` как переполнение передатчика. Это разные события.


## API

Интерактивная документация: `/docs`.

- `GET /api/current` возвращает последние корректные значения, состояния, ошибки и связь.
- `GET /api/analysis?start=...&end=...` принимает период в Unix-секундах, возвращает данные графиков, интервалы и статистику.
- `GET /api/thresholds?start=...&end=...` возвращает по каждому каналу гистограмму значений периода и рекомендуемый порог T с гистерезисом H: T ставится в зону минимальной плотности между двумя основными кластерами значений, полоса `[T - H/2, T + H/2]` покрывает эту зону (включение строго выше, выключение строго ниже). Рекомендация — отправная точка для калибровки и не сохраняется в настройки.
- `GET /api/settings`, `PUT /api/settings` читают и сохраняют полную конфигурацию, которую проверяет Pydantic.
- `GET /api/events?limit=100` возвращает последние диагностические события без BEAT (1-1000). BEAT сохраняется в БД и отображается временем последнего сигнала в статусе связи.
- `DELETE /api/history` удаляет историю с JSON-телом: `{"scope":"all","confirm":true}` либо `{"scope":"period","start":100,"end":200,"confirm":true}`. Границы задаются конечными Unix-секундами, `start < end`. Для `all` границы не задаются. Ответ `{"deleted":{"groups":0,"records":0,"events":0}}` содержит фактическое число удалённых групп, записей (измерения и статусы ошибок) и событий. Отсутствующее/ложное подтверждение и некорректные границы дают HTTP 422 без удаления.

Исходные записи лежат в SQLite (`groups`, `records`), диагностические события в `events`, настройки в `settings`. Значения хранятся целыми тысячными, SEQ целым 0-255, исходная строка в `raw`; порядковый номер в группе хранится в `position`.

Пересчёт учитывает всю предшествующую историю, чтобы верно определять состояние внутри гистерезиса. На большой многолетней БД это может быть медленно; агрегации, кэш и ограничение/прореживание графиков не реализованы. История не обрезается скрыто. Рекомендуется выбирать короткие периоды для графиков.
